# 2026-10-07 — Intel SKU Dataset Setup and Exploration

## Objective

Set up the repository for the Intel SKU cold-start forecasting experiments, identify the required source data, and complete exploratory analysis before implementing the preprocessing pipeline.

## 1. Dataset

The primary dataset for the current phase is the Intel microprocessor demand dataset.

### Original source

The granular dataset was obtained from the repository containing the Intel microprocessor sales data:

- Repository: https://github.com/xjguo9217/ensembles-of-life-cycle-forecasts/tree/main/Intel%20Microprocessors%20Sales
- Original dataset: https://github.com/INFORMSJoC/2022.0136/blob/main/data/MSOM_data/msom.2020.0933.csv

### `msom.2020.0933.csv`

This is the primary source for the experiment pipeline.

The file contains 26,114 rows and eight columns:

- `Distribution Center`
- `Product Offering`
- `Generation`
- `SKU`
- `ASP Group`
- `Week`
- `Forecasted Demand`
- `Customer Orders`

Each row represents a recorded observation for a particular SKU, distribution center, and week.

The dataset contains product attributes, recorded forecasts, and customer orders at the distribution-center level.

### `Intel_actual_demand.csv`

Contains weekly demand in wide format, with one row per week and one column per SKU in addition to the `Week` column.

It contains 187 weekly observations and 86 SKU demand series.

This file represents aggregated customer orders across distribution centers and will be used as an independent consistency check against the original source.

### `startend_date.csv`

Contains lifecycle information for the 86 SKUs:

```text
sku | start | end
```

These fields describe the recorded lifecycle intervals and are useful for validation and lifecycle analysis. The end week must not be used as a cold-start retrieval feature when it represents future information unavailable at prediction time.

## 2. Raw Data Directory

The raw data directory contains the original files without modification:

```text
data/
└── Intel_SKU/
    ├── raw/
    │   ├── msom.2020.0933.csv
    │   ├── Intel_actual_demand.csv
    │   └── startend_date.csv
    └── processed/
```

The original granular source is retained as the primary input. The other files are retained for cross-validation and lifecycle checks; redundant derived data can be regenerated during preprocessing.

## 3. Exploratory Notebook

Notebook:

```text
notebooks/exploration/01_intel_sku_analysis.ipynb
```

The notebook inspects the source schemas, dimensions, SKU coverage, lifecycle information, demand distributions, missingness, and static SKU attributes.

### Static attributes

The following fields are treated as static product attributes:

- `Product Offering`
- `Generation`
- `ASP Group`

The notebook checks that these attributes remain constant within each SKU and checks for missing attribute values.

The SKU identifier is retained as a key for associating metadata with demand histories

## 4. Forecasting Target and Features

The initial prediction target is `Customer Orders`.

`Forecasted Demand` is retained as a recorded forecast in the original dataset. It may be evaluated as a benchmark after its forecast timing and horizon are verified.

The planned feature roles are:

- Static retrieval metadata: `Product Offering`, `Generation`, and `ASP Group`.
- Time-series context: historical customer orders.
- Indexing and alignment: `SKU`, `Week`, and, for center-specific experiments, `Distribution Center`.
- Prediction target: future customer orders.

Future lifecycle information must not leak into cold-start retrieval.

## 5. Planned Experiments

Six configurations are planned across two forecasting settings.

### A. Aggregate across distribution centers

1. `001_raid`
2. `002_raid_sundial`
3. `003_gat_sundial`

The target is total customer orders per SKU and week, aggregated across distribution centers.

### B. Forecast separately for each distribution center

4. `004_raid`
5. `005_raid_sundial`
6. `006_gat_sundial`

The target is customer orders for an individual SKU, distribution center, and week.
